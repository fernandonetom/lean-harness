# Changesets

Hello and welcome! This folder has been automatically generated by `@changesets/cli`, a build tool that works
with multi-package repos, or single-package repos to help you version and publish your code. You can
find the full documentation for it [in the repository](https://github.com/changesets/changesets).

## Adding a changeset

When your PR includes user-facing changes (features, fixes, breaking changes), add a changeset:

```bash
npm run changeset
```

This interactively asks what kind of change (patch, minor, major) and records it in a `.md` file here.

## How releases work

1. Push your PR with a changeset file.
2. When merged to `main`, the CI workflow creates/updates a **"Version Packages"** PR.
3. Merging that PR automatically:
   - Bumps the version in `package.json`
   - Updates `CHANGELOG.md`
   - Creates a git tag
   - Creates a GitHub Release
   - Publishes to npm

## Skipping changesets

For docs, CI config changes, or other non-package-facing changes, you can skip the changeset requirement
by using an empty changeset: run `npm run changeset` and select the package then press Enter through the prompts.

If a changeset check fails in CI but your change doesn't need one, add a comment explaining why.
