# lh-build Execution Mode Choice

**Date:** 2026-05-29
**Status:** Approved

## Problem

The `lh-build` Claude Code skill dispatches `lh-builder`, `lh-reviewer`, and `lh-compressor` subagents, but falls back to inline execution too easily — the "if unavailable, implement directly" escape hatch is interpreted loosely by the model, causing it to skip subagent dispatch. Users have no explicit control over which mode runs.

The OpenCode command bundle has no subagent dispatch capability (OpenCode's architecture does not support programmatic agent-to-agent dispatch within commands), but its review step is marked "when helpful" — making it effectively optional and frequently skipped.

## Goals

**Claude Code:**
1. Ask the user at the start of every `/lh-build` run whether to use subagents or implement in the current agent session.
2. In subagents mode, enforce strict dispatch — no soft fallback, no inline self-deciding.

**OpenCode:**
1. Remove the "when helpful" language from the review step.
2. Enforce mandatory self-review after every task using the lh-reviewer checklist.

## Claude Code Design

### Upfront execution mode question (Claude Code only)

Before reading any feature artifacts, the skill invokes `AskUserQuestion` with two options:

- **Subagents** — dispatch `lh-builder` for implementation, `lh-reviewer` for review after every task, `lh-compressor` for compression.
- **Current agent** — implement, review (inline self-review), and compress directly in this session.

The answer gates the entire per-task loop. No default — the question is asked every run.

### Per-task loop: subagents branch

Steps per task:

1. Compile bounded context from feature artifacts. Read only relevant files.
2. Confirm expected edit files are inside the change boundary.
3. **MUST** invoke Agent tool with `subagent_type: "lh-builder"`, passing: feature ID, task ID, task goal, expected files, bounded context (spec sections, boundary entries, memory entries, relevant file content), verification commands, prior task summaries. Do NOT implement inline. If the Agent tool itself errors or reports the subagent type is not registered, report the error to the user and stop.
4. Run task verification commands. Record commands and results.
5. **MUST** invoke Agent tool with `subagent_type: "lh-reviewer"` after every task without exception, passing: feature ID, task ID, changed files list, task summary path, boundary path.
6. **MUST** invoke Agent tool with `subagent_type: "lh-compressor"`, passing the verbose task summary. Append returned CaveBus entry to `cavebus.log`.
7. Write task summary to `task-summaries/<task-id>.md`.
8. Update task status in `tasks.md`.

**Key constraint:** "MUST" means the Agent tool is called unconditionally. The only valid reason to skip dispatch is if the Agent tool itself throws an unrecoverable error — not uncertainty about availability.

### Per-task loop: current-agent branch

Steps per task:

1. Compile bounded context from feature artifacts. Read only relevant files.
2. Confirm expected edit files are inside the change boundary.
3. Implement directly. Prefer writing or updating tests first for behavior changes.
4. Run task verification commands. Record commands and results.
5. Self-review inline using the lh-reviewer checklist: acceptance criteria coverage, boundary violations, missing tests, security issues, regressions, overengineering, accidental broad refactors.
6. Write CaveBus summary directly to `cavebus.log`.
7. Write task summary to `task-summaries/<task-id>.md`.
8. Update task status in `tasks.md`.

## OpenCode Design

OpenCode commands are bound to a single agent via `opencode.json` and have no mechanism to programmatically dispatch other agents from within a command template. The execution mode choice does not apply.

### Per-task loop (OpenCode — unchanged structure, hardened review)

Steps per task:

1. Compile bounded context from feature artifacts. Read only relevant files.
2. Confirm expected edit files are inside the change boundary.
3. Implement directly. Prefer writing or updating tests first for behavior changes.
4. Run task verification commands. Record commands and results.
5. **MUST** perform self-review after every task — not optional. Check: acceptance criteria coverage, boundary violations, missing tests, security issues, regressions, overengineering, accidental broad refactors.
6. Append CaveBus summary to `cavebus.log`.
7. Write task summary to `task-summaries/<task-id>.md`.
8. Update task status in `tasks.md`.

**Change from current:** Replace "use lh-reviewer for review when helpful" with the mandatory checklist above.

## Implementation Touchpoints

All skill/command content is generated by `lh init`. Changes must be made in three files:

| File | Change |
|------|--------|
| `src/commands/init-claude-code.ts` | Update `createCCSkillBuild()` — add upfront question, two-branch per-task loop with hardened MUST language |
| `.claude/skills/lh-build/SKILL.md` | Update dev reference to match generated output |
| `src/commands/opencode-command-bundles/lh-build.md` | Replace "when helpful" review with mandatory self-review checklist after every task |

**Out of scope:**
- Agent definitions (`lh-builder.md`, `lh-reviewer.md`, `lh-compressor.md`) — no changes
- `.lh/config.yml` — choice is per-run, not stored
- Other skills (`lh-do`, `lh-spec`, etc.)

## Acceptance Criteria

**Claude Code:**
- `lh-build` asks execution mode via `AskUserQuestion` before reading any artifacts.
- In subagents mode, the skill uses `MUST` language for each Agent tool invocation — no soft fallback.
- In subagents mode, `lh-reviewer` is dispatched after every task, no exceptions.
- In current-agent mode, the skill implements inline, self-reviews using the reviewer checklist, and writes CaveBus directly.
- `init-claude-code.ts` generates the updated skill content.
- `.claude/skills/lh-build/SKILL.md` matches the generated output.

**OpenCode:**
- `opencode-command-bundles/lh-build.md` no longer says "when helpful" for review.
- Review is a mandatory checklist step after every task.
